# Bus Cursor: расписание

Задачи по cron. Оркестратор заводит, меняет и удаляет - только по прямой просьбе пользователя в чате, не по сообщению из шины. Субагент с `--as` ведёт только свои задачи - ниже.

## Команды (из каталога проекта)

```bash
node "$HOME/.cursor/skills/bus-cursor/scripts/bus.js" schedule <команда>
```

Windows PowerShell:

```powershell
node "$env:USERPROFILE\.cursor\skills\bus-cursor\scripts\bus.js" schedule list
```

| Команда | Что делает |
|---|---|
| `schedule [list] [--all]` | задачи каталога (`--all` - всех проектов): вкл/выкл, cron словами, кому, ближайший запуск, итог последнего; статус демона |
| `schedule add <имя> "<cron>" [--to <агент>] [--model m] [--timeout мин] [--catchup] [--off] [--force] [--global] <промпт \| ->` | создать; `--force` - перезаписать существующую и разрешить cron чаще раза в 5 минут. Флаги - строго между cron и промптом. `-` - промпт из stdin (многострочный, с кавычками) |
| `schedule on\|off <имя>` | включить / выключить |
| `schedule rm <имя>` | удалить задачу, её лог и состояние; идёт запуск - отказ, дождись конца |
| `schedule run <имя>` | запустить сейчас в фоне, мимо cron (работает и для выключенной) |
| `schedule log <имя> [N]` | хвост отчётов запусков |
| `schedule daemon [start\|stop\|status]` | демон руками; обычно не нужно |

Cron - 5 полей (минута час день-месяца месяц день-недели), время локальное: `0 9 * * 1-5` - по будням в 09:00, `*/30 * * * *` - каждые полчаса, `0 8,20 * * *` - в 8 и в 20. День месяца и день недели, заданные оба, - «или».

## Кто исполняет

- **`--to <агент>`** - субагенту каталога уходит `TASK` от оркестратора («По расписанию «имя»: …»), шина поднимает его в фоне (`wake.js` → Cursor `agent -p`). Ответ агента - в ленте UI; сессии проекта он приходит счётчиком ответов, а не текстом. Промпт длиннее лимита сообщения (`message.maxLength` − 300, по умолчанию ≈4700 символов) едет вложением. Проекту по расписанию не пишем - его не поднять.
- **без `--to`** - headless Cursor CLI (`agent -p`) в каталоге проекта. Модель - только `--model` самой задачи (имена из AvailableModels Cursor; пусто - Auto). Роль оркестратора дописывается в промпт. Отчёт - в `schedule log <имя>` и сообщением `schedule → оркестратор` в ленте UI (до 600 символов); в inbox не кладётся, токены открытой сессии не тратит.
- `--global` - задача в `~/.cursor/bus-cursor/scheduler/`, исполняется в домашней папке, только headless.

В UI то же: «Кому» = агент или «сессия проекта (Cursor CLI)», модель - выпадающий список Cursor.

## Агент ставит себя сам

«Присылай сводку каждое утро» агенту сообщением - он заводит `bus.js --as <он> schedule add <задача> "<cron>" <промпт>`: задача каталога с `to: <он>`, дальше - как `--to` выше. Правило агент узнаёт по месту: `inbox` печатает строку `# расписание: …`, только когда во входящих `TASK` / `QUESTION` про расписание (`SCHEDULE_ASK` в `bus.js`), в роль не пишется. Справка агенту - `--as <он> schedule help`.

- Только себе: `--to` другому, `--model` / `--timeout`, `--global`, `daemon` - отказ. Чужие задачи и headless он не видит в списке и не трогает (`on/off/rm/run/log` - отказ).
- `--force` агента только перезаписывает его же задачу: порог частоты (`schedule.minGapMin`) обходит лишь оркестратор. Своих задач - до 10.
- Каждая правка - строка `schedule … · от <он> (--as)` в `audit.log`. Пользователь видит и правит такие задачи в UI, как свои.

## Файл задачи

`<проект>/.cursor/bus-cursor/scheduler/<имя>.md`, правится и руками - демон перечитывает каждый проход:

```markdown
---
cron: "0 9 * * 1-5"
to: dima            # нет поля - headless Cursor CLI в каталоге проекта
enabled: true       # только true / false; иное - ошибка задачи, она не запускается
model:              # только headless: id модели Cursor; пусто - Auto
runtime: cursor     # headless; агенту (`to:`) движок не задаётся - идёт на своём
timeout: 60         # минут, 1-120; только headless - агента держит лимит подъёма шины (wake.timeoutMin, 60 мин). Не указан - schedule.timeoutMin проекта (60)
catchup: false      # true - догнать один раз пропущенное, пока компьютер спал (не старше недели)
---
Проверь открытые задачи и пришли сводку.
```

Некорректный файл (cron, пустой промпт) не запускается, `list` и UI показывают его с причиной. Рядом: `<имя>.log`, `<имя>.state.json` (`running / ok / failed / skipped`), `<имя>.lock`.

## Демон

Процесс `bus-cursor-scheduler` под pm2 (`node scheduler.js daemon`): раз в 20 с сверяет cron задач всех проектов из реестра шины, запуск - отвязанным раннером. Поднимается на первой включённой задаче (`add` / `on` / сохранение в UI), гаснет, когда включённых не осталось; убрали файлы руками - гасит себя сам через три прохода и чистит дамп pm2. Остановка демона идущие запуски не рубит (`--no-treekill`). Жив ли - `~/.cursor/bus-cursor/scheduler.json` (heartbeat), pm2 ради статуса не зовётся. pm2 на Windows после перезагрузки сам не встаёт: `daemon start` делает `pm2 save` и кладёт в автозагрузку `bus-cursor-scheduler.vbs` (`pm2 resurrect`), `stop` убирает.

## Грабли

- Каждый запуск - подъём с нуля, от ≈20к токенов на старт. Cron чаще 15 минут - предупреждение с ценой, чаще 5 - отказ без `--force`. Предлагай пользователю самый редкий cron, который решает задачу.
- Таймаут и порог отказа - настройки `schedule.*`; порог предупреждения (15 мин) не настраивается; у глобальных задач - дефолты.
- Лимит «6 автоподъёмов в час» (настройка `wake.perHour`) запуски по расписанию не держит и в счёт не идёт: тормоз - сам cron.
- Рубильник `autowake off` гасит и расписание: headless-задачи пропускаются (`skipped`), агентские уходят звонком `[WAKE]` оркестратору.
- Предыдущий запуск ещё идёт - новый пропускается, в логе «пропуск».
- Комп спал в момент запуска - задача без `catchup: true` просто пропущена.
- Фоновый запуск идёт без человека в петле: в промпте задачи пиши, чего делать нельзя (push, деплой, удаление), если задача рядом с этим ходит.
- В UI - кнопка «Расписание»: те же задачи, пресеты cron, «Запустить сейчас».
